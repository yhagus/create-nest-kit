# Generated API contract

Every generated project serves exactly this contract, whatever the platform, database, ORM, auth style and
validation library.
The e2e suite in `templates/base/test/e2e/` is the executable form of this document. When the two disagree,
fix one of them in the same change.

## Conventions

- Base path `/api/v1` (global prefix `api`, URI versioning). `/health` and `/docs` sit at the root.
- JSON in and out. Timestamps are ISO-8601 strings. Ids are **UUIDv7 strings**, generated by the app,
  in every variant (Mongo included, as `_id: String`).
- Emails are trimmed and lower-cased before validation, storage and lookup.
- Passwords are 8–128 characters.
- Lists take `?page=1&limit=20` (limit ≤ 100) and return `{ items, total, page, limit }`.
- Every error body is `{ statusCode, errorCode, message, details? }`. `details` carries field errors for
  `VALIDATION_FAILED`. Response bodies never reveal which policy or permission failed.
- Every handler declares exactly one of `@Public()`, `@Authenticated()` or `@RequirePermissions(...)`
  (from `src/auth/decorators.ts`). A handler with none is refused in both auth styles (deny by default): 401 for anonymous callers
  (authentication runs first), 403 `AUTH_FORBIDDEN` for signed-in ones.

## Error codes

| errorCode                       | Status | When                                                                       |
| ------------------------------- | ------ | -------------------------------------------------------------------------- |
| `VALIDATION_FAILED`             | 400    | request body or query failed validation; see [Validation](#validation)     |
| `BAD_REQUEST`                   | 400    | other 4xx without a specific code, e.g. malformed JSON or a non-UUID `:id` |
| `AUTH_UNAUTHENTICATED`          | 401    | missing, invalid or expired access token, or its session is revoked        |
| `AUTH_INVALID_CREDENTIALS`      | 401    | wrong email or password (same response for unknown email; constant-time)   |
| `AUTH_INVALID_REFRESH_TOKEN`    | 401    | unknown, expired, revoked or reused refresh token                          |
| `AUTH_INVALID_TOKEN`            | 400    | unknown, expired or already-used email-verification / password-reset token |
| `AUTH_INVALID_CURRENT_PASSWORD` | 400    | change password: current password is wrong                                 |
| `AUTH_EMAIL_NOT_VERIFIED`       | 403    | login while `EMAIL_VERIFICATION_ENABLED=true` and the email is unverified  |
| `AUTH_FORBIDDEN`                | 403    | authenticated but missing a permission, or no access decorator             |
| `NOT_FOUND`                     | 404    | unknown route or resource (including another user's session id)            |
| `USER_EMAIL_TAKEN`              | 409    | register / create / update with an email already in use                    |
| `USER_CANNOT_DELETE_SELF`       | 409    | an admin deletes their own account through `/users/:id`                    |
| `ROLE_NAME_TAKEN`               | 409    | role name already in use                                                   |
| `ROLE_PROTECTED`                | 409    | deleting or renaming a system role                                         |
| `CONFLICT`                      | 409    | other conflicts                                                            |
| `RATE_LIMITED`                  | 429    | throttler                                                                  |
| `INTERNAL_ERROR`                | 500    | anything unexpected (message is generic)                                   |
| `SERVICE_UNAVAILABLE`           | 503    | health check failed                                                        |

## Validation

Request bodies and query strings are validated by the project's validation library (Zod, class-validator, …).
Every library answers the same requests the same way:

- A failing request gets 400 `VALIDATION_FAILED` with `details: [{ field, errors }]`, one entry per failing field,
  sorted by `field` (numeric path segments compared as numbers), so the order is the same in every library.
  `field` is the dotted path of the property (`email`, `address.city`, `items.0.quantity`); a failing value of
  a list of plain values is reported at the list (`roleIds`, `permissions`).
- `errors` are human-readable messages. Their wording is library-specific: clients branch on `errorCode` and
  `field`, never on the messages.
- Unknown properties, in the body or the query string, are rejected: each one is a `details` entry of its own.
- A request without a body is validated as `{}`, so each required field is reported.
- Strings are trimmed where noted (emails, names, role descriptions, `search`); query numbers such as `page` and
  `limit` are converted from strings and take their defaults when missing.
- Malformed JSON and a non-UUID `:id` are 400 `BAD_REQUEST`, without `details`.

## Permissions and roles

```ts
export enum Permission {
  UsersRead = 'users:read',
  UsersCreate = 'users:create',
  UsersUpdate = 'users:update',
  UsersDelete = 'users:delete',
  RolesRead = 'roles:read',
  RolesCreate = 'roles:create',
  RolesUpdate = 'roles:update',
  RolesDelete = 'roles:delete',
  SessionsRead = 'sessions:read',
  SessionsRevoke = 'sessions:revoke',
}
```

- A role has `name` (unique, `^[a-z][a-z0-9-]{1,48}$`), `description`, `permissions: Permission[]` and `isSystem`.
- A user has any number of roles. Their effective permissions are the union of their roles' permissions.
- The seed (`db:seed`, idempotent) creates the system roles `admin` (every permission, re-synced on each run)
  and `user` (no permissions; given to every self-registered user). It also creates the admin user from
  `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD`, with a verified email and the `admin` role.
- System roles can't be deleted or renamed. Their description and permissions can change, except `admin`,
  whose permissions are always all of them.
- Deleting a role removes it from every user.

## Shapes

```ts
UserView    { id, email, name, emailVerified: boolean, roles: { id, name }[], permissions: Permission[], createdAt, updatedAt }
RoleView    { id, name, description, permissions: Permission[], isSystem: boolean, createdAt, updatedAt }
SessionView { id, userAgent: string | null, ip: string | null, createdAt, lastUsedAt, expiresAt, current: boolean }
TokenPair   { accessToken, refreshToken, expiresIn /* access token lifetime, seconds */, tokenType: 'Bearer' }
```

## Endpoints

Paths are relative to `/api/v1` unless they start with `/health`.

### Auth (`/auth`)

| Method & path                | Access            | Request                                   | Success                                               | Notes                                                                                                                                                          |
| ---------------------------- | ----------------- | ----------------------------------------- | ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/register`        | public, throttled | `{ email, password, name }`               | 201 `UserView`                                        | role `user`; queues `VerifyEmailMail` when verification is enabled; 409 `USER_EMAIL_TAKEN`                                                                     |
| `POST /auth/login`           | public, throttled | `{ email, password }`                     | 200 `TokenPair & { user: UserView }` + refresh cookie | creates a session (records `User-Agent` and client ip); 401 `AUTH_INVALID_CREDENTIALS`; 403 `AUTH_EMAIL_NOT_VERIFIED`                                          |
| `POST /auth/refresh`         | public            | `{ refreshToken? }` or the refresh cookie | 200 `TokenPair` + new cookie                          | rotates; reusing an already-rotated token revokes that session; 401 `AUTH_INVALID_REFRESH_TOKEN`                                                               |
| `POST /auth/logout`          | authenticated     | –                                         | 204, clears cookie                                    | revokes the current session                                                                                                                                    |
| `GET /auth/me`               | authenticated     | –                                         | 200 `UserView`                                        |                                                                                                                                                                |
| `PATCH /auth/me`             | authenticated     | `{ name }`                                | 200 `UserView`                                        |                                                                                                                                                                |
| `GET /auth/sessions`         | authenticated     | –                                         | 200 `SessionView[]` (active only, newest first)       | `current` marks the caller's session                                                                                                                           |
| `DELETE /auth/sessions/:id`  | authenticated     | –                                         | 204                                                   | own sessions only; 404 otherwise; effective **immediately**                                                                                                    |
| `DELETE /auth/sessions`      | authenticated     | –                                         | 204                                                   | revokes every session except the current one                                                                                                                   |
| `POST /auth/password/change` | authenticated     | `{ currentPassword, newPassword }`        | 204                                                   | revokes all other sessions; queues `PasswordChangedMail`; 400 `AUTH_INVALID_CURRENT_PASSWORD`                                                                  |
| `POST /auth/password/forgot` | public, throttled | `{ email }`                               | 202 (always)                                          | queues `ResetPasswordMail` only for a known email                                                                                                              |
| `POST /auth/password/reset`  | public, throttled | `{ token, password }`                     | 204                                                   | token single-use, `PASSWORD_RESET_TTL`; revokes every session; also verifies an unverified email (the link proves mailbox ownership); 400 `AUTH_INVALID_TOKEN` |
| `POST /auth/email/verify`    | public            | `{ token }`                               | 204                                                   | token single-use, `EMAIL_VERIFICATION_TTL`; 400 `AUTH_INVALID_TOKEN`                                                                                           |
| `POST /auth/email/resend`    | public, throttled | `{ email }`                               | 202 (always)                                          | queues a new `VerifyEmailMail` only for a known, unverified email; invalidates older tokens                                                                    |

Mail links point at the frontend: `${WEB_APP_URL}/verify-email?token=…` and `${WEB_APP_URL}/reset-password?token=…`.

### Users (`/users`)

| Method & path                           | Access            | Notes                                                                                                  |
| --------------------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------ |
| `GET /users?page&limit&search`          | `users:read`      | by email; `search` matches email or name, case-insensitive substring                                   |
| `GET /users/:id`                        | `users:read`      | 404 if unknown                                                                                         |
| `POST /users`                           | `users:create`    | `{ email, password, name, roleIds?, emailVerified? }` → 201 `UserView`                                 |
| `PATCH /users/:id`                      | `users:update`    | `{ email?, name?, password?, roleIds?, emailVerified? }`; a password change revokes all their sessions |
| `DELETE /users/:id`                     | `users:delete`    | 204; revokes their sessions; 409 `USER_CANNOT_DELETE_SELF`                                             |
| `GET /users/:id/sessions`               | `sessions:read`   | `SessionView[]` (`current` always false)                                                               |
| `DELETE /users/:id/sessions/:sessionId` | `sessions:revoke` | 204; effective immediately; 404 if the session isn't theirs                                            |

Unknown `roleIds` are a 400 `VALIDATION_FAILED`.

### Roles and permissions

| Method & path       | Access         | Notes                                                                                   |
| ------------------- | -------------- | --------------------------------------------------------------------------------------- |
| `GET /roles`        | `roles:read`   | all roles, by name (no pagination)                                                      |
| `GET /roles/:id`    | `roles:read`   |                                                                                         |
| `POST /roles`       | `roles:create` | `{ name, description?, permissions }` → 201 `RoleView`; unknown permission values → 400 |
| `PATCH /roles/:id`  | `roles:update` | `{ name?, description?, permissions? }`; `ROLE_PROTECTED` rules above                   |
| `DELETE /roles/:id` | `roles:delete` | 204; `ROLE_PROTECTED` for system roles                                                  |
| `GET /permissions`  | `roles:read`   | `Permission[]` (every enum value)                                                       |

### Health

`GET /health` (public): 200 when the database and Redis are up, 503 `SERVICE_UNAVAILABLE` otherwise.

## Auth semantics (both styles)

- **Access token:** a JWT carrying `sub` (user id) and `sid` (session id). Lifetime `ACCESS_TOKEN_TTL` (default `15m`). Sent as
  `Authorization: Bearer`. Signed with `JWT_SECRET` (≥ 32 bytes).
- **Refresh token:** opaque, delivered in the JSON body **and** as a cookie named `refresh_token`
  (`HttpOnly`, `SameSite=Strict`, `Path=/api/v1/auth`, `Secure` unless `NODE_ENV=development|test`, `Max-Age` = refresh lifetime).
  `REFRESH_TOKEN_TTL` (default `30d`) is a sliding lifetime; a session never outlives `SESSION_ABSOLUTE_TTL` (default `90d`)
  from its creation. Each refresh rotates the token; presenting a rotated-away token revokes the whole session.
- **Session:** one row per login (device). `lastUsedAt` updates on each refresh. Revoking a session (logout, revoke one,
  revoke others, password change/reset, admin revoke, user delete) makes its refresh token unusable **and** its
  access tokens unusable immediately. Every authenticated request checks the Redis deny-list
  `auth:revoked-session:<sid>` (TTL = access token lifetime).
- **Email verification** (`EMAIL_VERIFICATION_ENABLED`, wizard default true): when on, register queues a verification
  mail and login refuses unverified users with 403 `AUTH_EMAIL_NOT_VERIFIED`. When off, no verification mail
  is sent and login doesn't check. The verify/resend endpoints still work either way.
- **Throttling:** register 5/min, login 10/min, forgot/resend 3 per 15 min, reset 10 per 15 min (per client ip),
  global default `THROTTLE_LIMIT` per `THROTTLE_TTL`. The auth limits are read from config
  (`AUTH_THROTTLE_*`) so tests can lower or raise them.
- **CSRF** (`CSRF_ENABLED`, wizard default true): Nest's `enableCsrfProtection({ trustedOrigins: CORS_ORIGINS })`.
  It rejects cross-site state-changing browser requests (403). Non-browser clients are unaffected.
- **Passwords:** argon2id (hand-rolled) or scrypt (`@nestjs/authentication`). Random tokens (refresh, verification,
  reset) are 256-bit and stored as SHA-256 hashes, never raw.

## Data model (logical)

| Entity                                                                     | Fields                                                                                                                                             |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `users`                                                                    | id, email (unique), password_hash, name, email_verified_at?, created_at, updated_at                                                                |
| `roles`                                                                    | id, name (unique), description, permissions (string[]), is_system, created_at, updated_at                                                          |
| `user_roles`                                                               | user_id → users (cascade), role_id → roles (cascade); PK (user_id, role_id). In Mongo: `users.roleIds[]`                                           |
| `sessions`                                                                 | id, user_id → users (cascade), user_agent?, ip?, created_at, last_used_at, expires_at, absolute_expires_at, revoked_at? (identical in both styles) |
| hand-rolled only: `session_refresh_tokens`                                 | session_id (PK) → sessions (cascade), token_hash; rotation is a compare-and-set on token_hash                                                      |
| hand-rolled only: `verification_tokens`                                    | id, user_id → users (cascade), purpose (`email_verification` \| `password_reset`), token_hash (unique), expires_at, created_at                     |
| official only: `auth_refresh_tokens`, `auth_email_tokens`, `auth_sessions` | the `@nestjs/authentication` store records; `auth_refresh_tokens` adds `session_id` taken from `claims.sid`                                        |

Repository methods are each atomic (conditional UPDATE/DELETE … RETURNING, `findOneAndDelete`, compare-and-set).
No flow needs a transaction spanning two repositories.

## Environment (auth-related; see `src/config/env.ts` for the rest)

`JWT_SECRET` (secret), `ACCESS_TOKEN_TTL=15m`, `REFRESH_TOKEN_TTL=30d`, `SESSION_ABSOLUTE_TTL=90d`,
`EMAIL_VERIFICATION_ENABLED` (from the wizard), `EMAIL_VERIFICATION_TTL=24h`, `PASSWORD_RESET_TTL=1h`,
`AUTH_THROTTLE_REGISTER=5/1m`, `AUTH_THROTTLE_LOGIN=10/1m`, `AUTH_THROTTLE_MAIL=3/15m` (forgot password and resend
verification), `AUTH_THROTTLE_RESET=10/15m` (each `<limit>/<duration>`), `TRUST_PROXY=false` (take the client ip from
`X-Forwarded-For`), `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD` (secret). Durations use `<n>s|m|h|d`.
